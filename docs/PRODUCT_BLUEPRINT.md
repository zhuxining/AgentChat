# AgentChat 产品蓝图

版本：v0.1  
状态：设计稿

## 1. 文档目的

本文定义 AgentChat 要做什么、服务谁、解决什么问题以及第一阶段的产品范围。

本文不讨论：

- 技术选型
- 系统进程
- 数据库
- 通信协议
- 编程语言
- 部署方式

这些内容统一放在《系统架构文档》中。

## 2. 产品定位

AgentChat 是一个以本地电脑为核心主机的多端 Agent 通讯产品。

用户可以拥有多个具有不同身份、人格、记忆和能力的 Agent，并通过桌面端、手机端或其他设备与它们持续对话、协作和管理任务。

它借鉴微信的通讯体验，但核心对象不是普通联系人，而是：

- 不同身份的 Agent
- 持续存在的会话
- 可被委托的任务
- 跨设备的工作状态

一句话定位：

> 一个属于个人的 Agent 通讯中心，让用户像联系不同的人一样使用不同能力的 Agent。

## 3. 产品愿景

未来，用户不需要面对一个能力模糊的通用聊天入口，而是拥有一组熟悉、稳定、分工明确的数字伙伴：

- 有事找私人助理
- 查资料找研究员
- 做规划找产品经理
- 管理文件找秘书
- 分析数据找顾问
- 写代码找工程师

这些 Agent 不是一次性聊天窗口，而是长期存在的数字角色：

- 记得长期上下文
- 了解自己的职责
- 可以使用被授权的能力
- 可以持续执行任务
- 可以在不同设备上被访问
- 可以在必要时主动通知用户

## 4. 要解决的问题

### 4.1 单一 AI 入口能力模糊

用户需要反复解释角色、目标、工作方式和上下文，难以形成稳定预期。

### 4.2 对话和任务割裂

用户和 AI 聊完后，仍然需要手动执行、跟进和检查任务，AI 没有形成持续工作的能力。

### 4.3 多设备之间缺少连续性

用户在电脑上开始的工作，无法自然地在手机或其他设备上继续。

### 4.4 Agent 的行为不可见、不可控

用户不知道 Agent 正在做什么、访问了什么、为什么失败，也无法方便地确认敏感操作。

### 4.5 用户无法拥有自己的 Agent

许多 AI 使用体验依附于一次性聊天窗口，用户难以长期管理 Agent 的身份、记忆、任务和权限。

## 5. 目标用户

### 第一目标用户：个人重度 AI 用户

典型特征：

- 经常使用 AI 处理工作和个人事务
- 同时需要研究、规划、写作、整理和执行等能力
- 有一台可以作为主要工作中心的电脑
- 关心隐私、数据归属和长期记忆
- 希望 AI 不只是回答问题，还能持续帮忙做事

典型人群：

- 独立开发者
- 产品经理
- 研究人员
- 内容创作者
- 自由职业者
- 小型创业者

### 第二阶段用户：家庭和小团队

他们需要共享部分 Agent，同时保留个人私有 Agent，并管理不同成员的权限。

第一阶段不以大型企业协作和公共社交网络为主要目标。

## 6. 核心产品目标

### 目标一：建立稳定的 Agent 身份

用户能够清楚理解每个 Agent：

- 它是谁
- 它负责什么
- 它擅长什么
- 它可以使用什么能力
- 它不能做什么

### 目标二：让用户自然地委托工作

用户不仅可以向 Agent 提问，还可以：

- 委托一次性任务
- 让 Agent 持续跟进
- 创建定时任务
- 监控某个主题或对象
- 要求 Agent 完成后主动通知

### 目标三：提供连续的多端体验

用户可以在一个设备上开始，在另一个设备上继续，不需要重新解释上下文。

### 目标四：让 Agent 的行为透明、可控

用户应该知道：

- Agent 当前正在做什么
- Agent 使用了什么能力
- 哪些操作需要确认
- 任务是否成功
- 失败后如何处理

### 目标五：让用户拥有和管理自己的 Agent

用户可以长期管理 Agent 的身份、会话、记忆、任务和权限，而不是只能使用一次性聊天窗口。

## 7. 产品概念模型

### 7.1 Agent

Agent 是一个长期存在的数字角色，拥有身份、职责、能力、记忆和任务状态。

### 7.2 会话

会话是用户与一个或多个 Agent 交流的空间，可以是：

- 用户与单个 Agent 的单聊
- 用户与多个 Agent 的群聊
- 某个任务的专属讨论
- 某个主题的长期工作空间

### 7.3 任务

任务是 Agent 被委托执行的工作，可以立即完成、持续运行、定时执行、等待确认、暂停、重试或取消。

### 7.4 设备

设备是用户访问 AgentChat 的入口。不同设备访问的是同一组 Agent、会话和任务。

### 7.5 记忆

记忆是 Agent 对用户、工作和历史上下文的长期了解。记忆应当具有明确范围，例如会话级、Agent 级、项目级或用户级。

## 8. 核心使用场景

### 场景一：私人助理

用户对私人助理说：

> 帮我整理今天的工作，并提醒我下午给客户回复。

Agent 能理解用户意图、形成待办事项、设置提醒，并在原会话中反馈结果。

### 场景二：研究与资料整理

用户把一组资料交给研究员：

> 帮我总结这些文档，并找出不同观点。

Agent 输出摘要、关键观点、差异和待验证问题，用户可以在其他设备上继续追问。

### 场景三：持续监控

用户说：

> 持续关注这个主题，有重要变化时通知我。

Agent 形成持续任务，并在发现重要变化时主动联系用户。

### 场景四：多个 Agent 协作

用户创建一个包含产品经理、设计师和工程师的群聊，由不同 Agent 分工完成需求分析。

不同 Agent 需要有明确职责，避免重复发言和互相抢答。

### 场景五：跨设备继续工作

用户在桌面端开始整理方案，离开电脑后通过手机：

- 查看最新消息
- 继续追问
- 查看任务进度
- 处理 Agent 的确认请求
- 接收完成通知

### 场景六：敏感操作确认

Agent 在执行删除文件、发送消息、修改外部数据等操作前，请求用户确认。

用户可以批准、拒绝、修改范围或只批准本次操作。

## 9. 核心产品能力

### 9.1 Agent 管理

- 创建、编辑和删除 Agent
- 设置 Agent 名称、头像和身份
- 配置 Agent 的职责和能力
- 查看 Agent 当前状态
- 管理 Agent 的记忆范围

### 9.2 会话管理

- 会话列表
- 单聊
- 群聊
- 会话搜索
- 固定、归档和删除
- 未读状态
- 消息历史
- 文件和其他消息类型

### 9.3 任务管理

- 从对话中创建任务
- 查看任务列表
- 查看任务进度
- 暂停、继续、取消和重试任务
- 查看任务结果
- 任务完成通知

### 9.4 Agent 状态与过程展示

需要区分：

- 空闲
- 思考中
- 查找资料
- 使用能力
- 等待用户确认
- 执行任务
- 已完成
- 执行失败

### 9.5 多端访问

- 关联新设备
- 查看同一组 Agent
- 查看同一批会话
- 继续发送消息
- 查看任务状态
- 接收通知
- 管理设备权限

### 9.6 权限和确认

- Agent 能力授权
- 设备权限
- 文件访问范围
- 敏感操作确认
- 操作记录
- 权限撤销

## 10. 核心用户流程

### 10.1 首次使用

~~~text
创建个人空间
    ↓
创建或选择 Agent
    ↓
了解 Agent 的身份和能力
    ↓
发起第一次对话
    ↓
完成一次真实任务
~~~

### 10.2 日常使用

~~~text
打开 AgentChat
    ↓
查看会话和任务状态
    ↓
选择 Agent
    ↓
发送消息或委托任务
    ↓
查看过程和结果
    ↓
继续追问或确认下一步
~~~

### 10.3 多端使用

~~~text
在主设备上关联新设备
    ↓
确认设备身份和权限
    ↓
查看已有 Agent 与会话
    ↓
在新设备上继续工作
~~~

## 11. 核心体验原则

1. **身份稳定：** Agent 必须有清晰、持续、可理解的身份。
2. **状态可见：** 用户能知道 Agent 当前在做什么。
3. **授权可控：** 用户始终能控制敏感操作。
4. **对话即入口：** 用户可以通过自然语言开始工作。
5. **任务可追踪：** 长任务不能被隐藏在聊天气泡中。
6. **跨端连续：** 切换设备不丢失上下文。
7. **主动但不打扰：** Agent 可以主动通知，但必须可管理。
8. **渐进式信任：** Agent 先展示能力，再逐步获得更高权限。
9. **失败可恢复：** 用户能理解失败原因并继续处理。

## 12. 产品边界

### 第一阶段要做

- 多个 Agent
- Agent 身份和配置
- 单聊
- 基础群聊
- 消息历史
- 基础文件交互
- 任务委托
- 任务状态
- 多端关联
- 消息同步
- 基础通知
- 用户确认流程

### 第一阶段不做

- 面向陌生人的公共社交网络
- Agent 公开市场
- 大规模企业组织管理
- 复杂朋友圈内容流
- 任意 Agent 之间的开放通信
- 无限制的自主高风险操作
- 复杂的商业计费体系

“像微信”主要借鉴会话列表、单聊、群聊、消息、未读、通知和多端连续性，不代表复制微信的全部产品范围。

## 13. MVP 定义

MVP 需要验证一个完整闭环：

> 用户创建一个 Agent，通过一个以上设备与它持续对话，并成功委托、跟踪和完成一项任务。

MVP 至少包括：

1. 创建一个可配置的 Agent
2. 与 Agent 单聊
3. 保存和恢复聊天记录
4. 展示 Agent 的执行状态
5. 委托一个后台任务
6. 查看任务进度和结果
7. 在第二个设备上继续会话
8. 对敏感操作进行确认
9. 接收任务完成通知

## 14. 产品阶段目标

### 阶段一：个人 Agent 通讯中心

用户可以拥有多个可靠的 Agent，并像联系人一样随时找到它们。

### 阶段二：多端 Agent 工作空间

用户可以在不同设备上持续访问同一组 Agent 和任务。

### 阶段三：主动工作的 Agent

Agent 不只是回答问题，还能持续跟进、监控和完成任务。

### 阶段四：家庭与团队共享

多人可以安全地共享部分 Agent、任务和知识，同时保留个人空间。

### 阶段五：Agent 生态

用户可以创建、组合、分享和扩展 Agent。

## 15. 成功标准

### 用户价值

- 用户能在一分钟内理解一个 Agent 的职责。
- 用户能在首次对话中完成一个真实任务。
- 用户愿意为不同任务主动选择不同 Agent。
- 用户能在切换设备后自然继续工作。
- 用户能理解 Agent 当前正在做什么。

### 产品行为

- 创建的 Agent 会被持续使用。
- 用户会从会话中主动委托任务。
- 后台任务能带来明显价值，而不是增加管理负担。
- 用户会主动返回查看 Agent 状态和结果。
- 多端关联后仍能保持稳定使用。

### 体验质量

- 消息不丢失。
- 任务状态可追踪。
- 用户确认不会被绕过。
- Agent 失败时能明确说明原因。
- 长任务可暂停、恢复或取消。

## 16. 产品蓝图结论

AgentChat 的本质不是在桌面应用中增加一个聊天窗口，而是建立一个长期存在的个人 Agent 空间：

~~~text
用户
 ├── 多个 Agent
 │    ├── 身份
 │    ├── 记忆
 │    ├── 能力
 │    └── 任务
 ├── 多个会话
 ├── 多个设备
 └── 持续的工作上下文
~~~

最终产品目标：

> 让每个人都拥有一组可信赖的数字伙伴，并能通过任何设备与它们持续沟通、委托工作和管理生活与工作。

本产品蓝图定义“做什么”；对应的《系统架构文档》定义“如何实现”。
