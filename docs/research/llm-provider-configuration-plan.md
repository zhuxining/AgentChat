# LLM 供应商接入与凭据配置规划

日期：2026-10-19。
状态：Q1–Q15 已获用户逐轮确认；多实例接入、凭据来源、模型覆盖、设置页与宿主凭据通道已实现并通过本地验证（见文末）。
事实依据：[pi-ai 供应商与凭据调研](pi-ai-providers.md)。当前版本为 pi-ai 1.3.0、pi-durable 1.2.0。

## 目标与范围

- 复用 pi-ai 内置供应商、聊天模型目录、协议适配器和认证公开接口。
- 开放完整聊天 Model 的可序列化字段，支持内置模型覆盖及自定义模型。
- 支持同一供应商的多个接入实例，分别配置地址、认证及模型覆盖。
- 纳入内置 API Key、OAuth 与云端 ambient 认证方式，按供应商实际能力展示必填参数。
- 请求级参数与 Model 定义分开规划。不能把 pi-ai 支持的所有 request options 直接视为 durable 已支持的设置；未经验证的选项不提供可用性承诺。
- 使用 AgentChat 自有配置合同，尽量保留 pi 模型字段名称和语义。不自动读取用户 Pi CLI 的默认配置，不承诺完整兼容 coding-agent 的文件格式。
- 不加入 shell 密钥命令，不新增 Agent 执行循环、调度、恢复或其他 runtime 框架。

## 领域对象与引用

| 对象         | 职责                                                              |
| ------------ | ----------------------------------------------------------------- |
| 供应商类型   | 内置 factory 与协议/认证能力，例如 openai、deepseek               |
| 接入实例     | 稳定 ID、展示名称、供应商类型、启停状态、连接、认证选择和模型配置 |
| 模型定义     | 属于接入实例的模型 ID、内置定义及覆盖，或自定义定义               |
| 凭据引用     | 所选来源及条目标识，不包含解析后的秘密值                          |
| Bot 模型引用 | 稳定的接入实例 ID + 模型 ID                                       |

实例名称用于展示，不承担引用身份。实现时需验证改写内置 provider ID 对认证、模型筛选、目录刷新和协议行为的影响；不能假定复制并改 ID 就足够。
已有 Bot、持久化会话的 DeepSeek 引用及旧系统凭据需要显式迁移，保持原有引用可解析，具体迁移格式待源码设计。

## 页面结构

```text
设置 → 模型供应商
         ├─ 接入实例列表
         ├─ 添加接入 → 选择供应商 → 连接与认证 → 选择模型
         └─ 实例详情
              ├─ 连接与认证
              └─ 模型列表 → 模型配置（常用表单 / 高级 JSON）
```

接入实例列表只展示用户建立的实例，显示名称、供应商类型、认证配置状态、地址摘要及待生效状态。内置供应商在添加流程中提供可搜索选择器。

连接与认证页按所选方式展示 API Key 来源、OAuth 登录状态或云认证参数。配置完整与连接测试成功分别显示。

模型页可浏览完整目录，支持搜索、自定义模型、编辑覆盖及恢复默认值。用户选择哪些模型在 Bot 选择器中出现；新建实例引导选择至少一个。Bot 选择器按实例分组。隐藏模型仅影响后续选择，不禁止已有引用执行。

模型编辑的常用表单包含名称、端点、上下文上限、输出上限、输入能力、推理能力等；复杂 compat、采样参数、价格分层等使用高级 JSON。两种编辑方式操作同一事实源，保存前统一运行时校验。展示字段是继承默认还是已覆盖，并允许查看隐藏秘密值的最终有效配置。

## 模型继承与覆盖

- 内置模型以随包目录为基线，仅保存用户修改的差异。
- 升级后未覆盖字段跟随新目录，已覆盖字段保留用户设置。
- 恢复默认值删除对应覆盖；不是删除内置模型。
- 自定义模型保存必要定义，按所用 API 校验字段及 compat。
- 上游模型移除时保留已有引用并报告诊断，不自动切换模型。
- 能力描述、请求参数和真正被适配器消费的配置需明确区分；界面不宣称所有字段都能强制执行限制。
- 认证 Header 等秘密值通过凭据引用管理，高级 JSON 和最终配置不回显解析值。

## 认证与凭据

| 方式/来源  | 页面行为                                                            |
| ---------- | ------------------------------------------------------------------- |
| 系统凭据库 | 输入新 key、替换、移除；保存后清空输入框，不回显已存 key            |
| 环境变量   | 配置变量名，显示后台是否读取到；页面不修改系统环境                  |
| 凭据文件   | 选择独立凭据文件及条目，支持写入/替换明文 key，或填写显式环境引用   |
| OAuth      | 使用供应商公开登录流程；Token 存系统凭据库，页面显示登录/退出与状态 |
| 云认证     | 按内置供应商要求配置账号、项目、区域等，并沿用其 ambient 认证语义   |

认证方式与 API Key 来源是两个层次。每个实例明确选择来源，选定来源读取失败直接报告，不静默降级到其他来源或其他账号。

凭据文件与普通配置分离。普通配置读取、编辑、导出和错误信息仅保留凭据引用。明文密钥仅经专门凭据入口写入，不借通用配置编辑器回传。
文件允许明文和显式环境引用；不支持 !command。精确的文件 schema、引用编码和模板语法在实现设计时确定，不能直接照搬 coding-agent 的解释器。

系统访问和可信持久化留在 Rust/宿主边界，Node 通过 pi-ai 公开 CredentialStore/AuthContext 接入认证。具体跨进程适配须验证 OAuth modify/刷新所需的并发一致性与持久化，不将 Token 轮换简化为无锁读写。
按实际引用的认证变量清理工具子进程环境。凭据文件的路径授权、读写范围、所有者权限及原子写入必须在实现时落实；这不意味着工具在同一用户权限下具有完整凭据隔离。

## 保存、生效和测试

- 保存验证配置有效以及所选凭据来源可解析；不自动调用模型或登录。
- 连接与模型配置变更首版统一在重启后台后生效，展示待生效标识与重启入口。
- 后台忙碌时提示正在执行的任务，由用户决定重启时机，不自动打断任务。
- 实际环境来源是后台宿主进程。子进程重启只继承启动它的进程环境；若宿主继承的是旧环境，必须从包含新变量的启动环境重启宿主。不能承诺在终端修改变量后点击重启即可自动获得新值。
- 提供单独的“测试连接”和“保存并测试”；测试需明确使用已保存的待生效配置还是当前生效配置，不能展示混淆状态。具体隔离实现待技术验证。
- 测试使用一个明确选择的模型发起小规模请求，记录时间、实例、模型及配置版本；区分来源读取、认证、网络、协议、模型错误。测试可能产生供应商费用。
- 测试成功仅证明该配置和模型在该次请求成功，不代表整个模型目录均可用。
- 配置发生变化后，旧测试结果保留版本信息或标记过期，不显示为新配置的成功证明。

## 停用与删除

- Bot 或已有会话引用接入实例、自定义模型时，阻止直接删除，展示引用位置。
- 接入实例可以停用，停用后不允许发起新的模型请求；历史会话仍可查看，重新启用后可继续使用。
- 首版配置变更按重启规则生效；待停用与已停用需区分。停用规则要覆盖恢复执行、压缩等模型请求路径，不能只禁用发送按钮。
- 删除内置模型覆盖仅恢复默认值，不改变 Bot 或会话引用。
- 不自动把已有引用迁移到另一个实例、账号或模型。

## 实施前必须验证的技术边界

以下是工程事实调查与设计工作，不要求用户判断源码事实：

1. 接入实例 ID 与 pi 内置 provider 认证/协议身份的组合方式，以及旧 Bot/会话引用的迁移。
2. 当前 durable 公开接口能承载哪些请求级参数；不使用私有 API、类型断言或自建执行循环补齐。
3. OAuth 各流程在独立后台、桌面回调和取消中的生命周期；CredentialStore 串行 modify 与系统凭据库存储的衔接。
4. 独立凭据文件的 schema、选定文件的访问授权及跨平台权限；防止通过引用获取任意本地文件内容。
5. 保存前检查、待生效配置测试与运行中 Harness 的隔离方式，避免测试修改正在使用的 registry。
6. 重启对正在执行任务和恢复执行的实际影响；停用在所有模型请求路径上的约束方式。
7. 远端目录的显式刷新和缓存策略。内置静态目录不隐式执行全网发现。

## 验收重点

- 同一供应商两个实例的地址、凭据、目录及 Bot 引用互不串用。
- 环境变量、文件、系统凭据库分别生效；来源失败不会自动换来源。
- OAuth 登录、刷新、退出、取消及持久化错误可观察且不泄密。
- 表单与 JSON 配置一致；默认继承、覆盖、恢复和模型移除诊断正确。
- 保存不产生模型请求；连接测试绑定明确的配置版本和模型。
- 待生效、后台重启、停用、引用保护与历史查看符合上述规则。
- 普通配置读取、导出、日志和错误不包含解析后的 key、Token 或认证 Header。
