# AgentChat UI 结构

> **Status**: active。Bot 列表、产品聊天窗口、详情、配置编辑与设置页面已实现；桌面三栏/两栏与页面导航已完成 macOS 冒烟。窄屏单栏受桌面窗口最小宽度限制，尚未在真实窗口验证。

本文件描述界面的信息架构、布局规则与状态归属。执行机制、配置所有权与生命周期见[架构总览](00-overview.md)，产品定位见[产品蓝图](../PRODUCT_BLUEPRINT.md)，概念定义见[术语表](../../GLOSSARY.md)。

文中「产品聊天窗口」指术语表中的产品 Conversation：用户与 Bot 连续协作的界面容器，一条连续消息流可以汇集多个库 Conversation。界面不使用「会话」单指其中任一层。

## 信息架构

Bot 是唯一入口。用户从 Bot 列表进入某个 Bot 的产品聊天窗口，在窗口内查看该 Bot 的详情与配置；不建立独立的 Bot 管理后台，也不以库 Conversation 列表作为首页。

```text
Bot 列表
├─ 选择一个 Bot → 产品聊天窗口
│                    ├─ Bot 详情（简单项行内改，内容多的弹窗编辑）
│                    └─ 应用设置（列表底部）
└─ 新建 Bot → 创建后进入该 Bot 的聊天窗口
```

应用设置独立于 Bot 配置，分类为通用、模型与 Provider、Runner、关于。Bot 专属的模型、指令、工作区与工具在 Bot 详情中修改；Provider 凭据与 Runner 生命周期只在设置中修改。设置是独立视图，不保留 Bot 列表栏，其左侧分类栏底部提供返回工作区的入口。

## 布局与自适应

桌面（≥ 768px）是一个可拖拽的三栏工作区：Bot 列表与 Bot 详情都是可调宽度的面板，详情由聊天页右上角按钮推入或收起，不随窗口宽度自动出现；面板宽度可拖拽调整，拖动只改变宽度，不改变当前页面或草稿。窄屏退化为页面栈，详情重新成为独立页面。两种形态共用同一套视图组件，不使用抽屉。

| 可用宽度 | 呈现                                               | 详情入口             |
| -------- | -------------------------------------------------- | -------------------- |
| ≥ 768px  | 可拖拽面板：Bot 列表丨聊天窗口丨Bot 详情（可收起） | 右上角展开／收起按钮 |
| < 768px  | 单个页面：列表／聊天／详情／设置                   | 聊天页顶部进入详情页 |

窄屏首页就是 Bot 列表本身，桌面由左栏面板承载；两种布局共用同一份列表实现，搜索词等界面状态不随布局切换重置。布局形态由媒体查询决定，面板之外的样式优先用 CSS 响应式规则。窗口最小宽度为 400px，平板与手机宽度可以直接在桌面窗口内验证；面板之间的分隔由拖拽手柄提供，面板自身不再叠加边框。

## 页面职责

| 路由                   | 页面                                 | 内容                                                         |
| ---------------------- | ------------------------------------ | ------------------------------------------------------------ |
| `/`                    | Bot 列表页（窄屏）／选择提示（宽屏） | 搜索、Bot 条目、新建入口、设置入口                           |
| `/bots/new`            | 新建 Bot                             | 一次性完整表单，默认值取自 Runner 的 `botDefaults`           |
| `/bots/$botId`         | 产品聊天窗口                         | 消息流、Conversation 分隔、发送与停止、执行状态              |
| `/bots/$botId/details` | Bot 详情（窄屏）                     | 桌面由详情面板代替；资料、运行方式、能力、当前状态与工作目标 |
| `/settings/$section`   | 应用设置                             | 分类导航与对应内容，侧栏底部返回工作区                       |

Bot 详情是唯一的 Bot 编辑入口，没有独立编辑页：服务商、模型、思考级别、名称等简单值在行内直接修改，指令、工作目录、能力选择等内容多的项用弹窗编辑，归档经确认弹窗执行。详情内容同时用于宽屏右栏与独立详情页。Bot 条目显示名称、最近一句消息与运行状态；运行状态来自该 Bot 最新的库 Conversation，非选中 Bot 只在过时窗口内读取一次。

## 连续消息流

一个 Bot 可以拥有多个库 Conversation。界面按时间把它们拼接为一条消息流，边界以轻量分隔标注，用户不需要切换底层 Conversation 才能阅读历史；选中 Bot 默认停在它最新的一个。工作目标属于单个库 Conversation，其保存与完成状态由用户确认。

消息区使用 `MessageScroller` 与 `Message` 组件，不自建滚动行为：每一行（消息、会话分隔、排队与执行状态）都是 `MessageScrollerItem`，消息表面用 `Bubble`（用户 primary、助手 muted，宽度随内容且不超 80%），用户消息标记为锚点；`autoScroll` 只在读者位于实时边缘时跟随流式输出，读者一旦向上滚动就保持原位；打开对话定位到最后一段锚点而不是绝对底部；新会话在输入时先把它带到视口上方再让回答流入下方。行 id 由库 Conversation 与消息 id 组合而成，因为消息 id 只在单个 Conversation 内唯一；“跳到最新消息”控件由组件提供。

消息流只渲染用户与助手的文本消息，工具与系统条目不上屏，气泡也不再标注发送者姓名——左右对齐与气泡颜色已经表达归属；原始记录仍保留在 Runner 侧。

会话分隔、排队提示与执行中状态等非消息行使用 `Marker`（分隔用 `separator` 变体，进行中状态带 `role="status"` 与 Spinner）；空状态统一使用 `Empty` 的 header／media／content 组合，不手写居中布局。

会话快照尚未到达时，聊天区与详情展示稳定的加载状态；只有确认读取成功且内容确实为空时才展示「开始这次对话」，刷新失败保留已加载内容并在聊天顶部提示。入场动画按 Conversation 比较前后两次渲染的最新行：只有同一会话中新到的一行才播放位移／淡入，切换 Bot、重新挂载或加载历史都不重放。

提交与撤回遵循库契约：输入以稳定 requestId 提交，未确认时重试复用同一 requestId；撤回排队输入与停止当前执行是两个独立操作。

设置页各分类同时保持挂载，隐藏的分类从可访问性树中移除而保留组件状态；这样切换分类不会丢失配置编辑或凭据输入草稿，离开设置页则随布局卸载一并清理。

## 组件与复用边界

```text
src/
├─ app/            路由、应用装配、Runner 客户端与工作区状态
├─ features/bots/  Bot 列表、详情、配置表单与草稿
├─ features/chat/  聊天窗口视图、Conversation 时间线
├─ features/settings/ 设置分类、配置编辑器
└─ components/ui/  共享基础组件
```

页面负责路由参数、返回入口与内容装配；功能组件负责展示与交互；`app/` 负责路由与布局组合。复用发生在三层：同一 Bot 列表同时用于左栏与窄屏首页，同一聊天视图同时用于中栏与窄屏聊天页；同一 Bot 详情内容同时用于宽屏右栏与独立详情页；能力选择控件（Extension 与 Tool 联动）在新建表单与详情弹窗共用。

简单值行内编辑、内容多的项弹窗编辑的划分只在详情内，新建仍是一次性完整表单：创建需要一次性拿全部字段，建成后的修改多是单字段的。这两种形态共享字段控件，不共享提交流程。

业务组件放入所属功能目录，跨功能共享的展示组件上移到 `components/ui/`；只为已有消费者提取抽象，不预建通用表单或页面框架。

## 状态归属

| 状态                                 | 归属与保存方式                                                                           |
| ------------------------------------ | ---------------------------------------------------------------------------------------- |
| Bot、会话目录、能力、配置状态        | Runner 为事实来源，TanStack Query 缓存 `initialize` 结果                                 |
| 会话快照、消息、执行状态、已保存目标 | TanStack Query 按 Conversation ID 缓存；摘要、历史与当前聊天共享快照                     |
| 当前页面与当前 Bot                   | TanStack Router 参数；内存历史，不维护第二份 Bot 选择状态                                |
| 设置页返回位置                       | 路由 search 的 `returnBotId`；返回时校验 Bot 仍存在且未归档                              |
| Bot 列表搜索词、列表及详情面板开关   | 工作区 UI Zustand Store，跨页面保留                                                      |
| 未发送输入、未确认提交               | 聊天草稿 Zustand Store；输入按 Bot 保存，全局最多一条未确认提交                          |
| 工作目标草稿                         | 聊天草稿 Store，按 Conversation ID 与已保存目标的 `updatedAt` 关联                       |
| 配置编辑草稿、凭据输入、Bot 编辑弹窗 | 组件状态；设置各分类保持挂载，切换分类不丢未保存草稿；离开设置卸载后清理                 |
| 操作 pending 与错误                  | TanStack Mutation；同一 Bot、Conversation 或 Runner 控制组共享 pending，错误在发起处展示 |
| 面板动画、滚动资源                   | 视图及现有滚动组件拥有生命周期，清理定时器与资源                                         |
| 主题与字号偏好                       | 计划归属 UI 本地偏好，当前尚未开放                                                       |

`workspace-provider.tsx` 仅提供稳定的 Runner 客户端与聊天草稿 Store 实例；`workspace-ui.tsx` 创建工作区 UI Store。两个 Store 随 Provider 创建，实例在挂载期间保持稳定；不启用 `persist`，应用重新挂载时清空。共享 Store 不保存密钥、Runner 快照或可推导的执行状态。

组件通过 selector 订阅所需字段，多个字段组成对象时使用 `useShallow`；不订阅整个 Store。表单的局部输入继续使用组件状态，不因使用 Zustand 而扩大共享范围。Bot 列表、设置页不会因聊天草稿变化而更新。

`app/runner-queries.ts` 集中定义 Query Key、快照读取与 Runner 代次检查。RuntimeGate 的首次初始化直接填充同一目录缓存，工作区不重复初始化。当前聊天的独立轮询观察者每 1.2 秒刷新快照；摘要和历史按 10 秒新鲜度复用缓存及进行中的请求，不另建缓存或轮询器。Bot、聊天、设置操作分别位于对应功能目录的 `use-*-actions.ts`；`use-bot-chat.ts` 只组合聊天及详情所需的数据与操作。

提交固定捕获原 Bot、Conversation、文本、草稿修订号及 requestId。接纳结果未知时保留原请求，跨页面重试复用 requestId，不能用另一条输入替代。接纳成功只清理原 Bot 未继续修改的草稿；另一 Bot 仍可编辑草稿。提交确认及其展示刷新完成前保持发送锁，不能让按钮显示可发送而实际静默拒绝。

停止或重启 Runner 时先暂停 Query 并取消旧请求。重启清空全部快照后重新初始化，再恢复读取；停止失败恢复读取，重启失败保持暂停并提供重试。IPC 无法物理取消，因此异步工作流在应用响应或发起后续读取前检查 Runner 代次，防止旧操作刷新已停止的 Runner，或覆盖重启后的目录。Runner 控制组的 pending 跨设置分类共享，避免页面卸载后并发停止、重启。

配置写入由 Runner 校验并原子落盘。UI 发现外部修改时拒绝覆盖并保留草稿；保存后的 Bot 配置用于后续执行，已有执行需在空闲时显式应用，界面必须区分这两者。

后台 Runner 独立于 UI 长期运行，因此界面可能比它新：响应中的新增字段必须按可选处理并回退到本地已有值（例如 provider 选项缺失时保留下拉当前值），不能假设响应形态与当前前端版本一致。

## 交互与可访问性约束

- 保留无边框窗口与透明标题栏：自定义拖拽区不得覆盖按钮、输入框等交互控件。
- 新交互支持键盘操作与可见焦点，输入框、按钮、列表与弹层提供语义标签。
- 图标统一使用 `lucide-react`；颜色与主题取自 `src/index.css` 的主题 Token，不硬编码重复色值。
- 加载、空列表、连接失败、执行错误与配置无效都有明确反馈，异步界面区分 idle／loading／success／empty／error。
- 成功操作不产生常驻通知（默认成功）；失败只在操作所在页面或聊天顶部提示一次，不在同屏区域重复同一条错误。
- 动效克制：状态变化与面板推拉用 150–200ms 过渡，新内容入场只做轻微位移或淡入（仅最新一轮消息播放），拖拽与流式文本不做动画；`prefers-reduced-motion` 命中时全部降级为瞬时。

## 验证与缺口

UI 测试位于 `tests/ui/`，覆盖提交与轮询、输入法确认、按 Bot 草稿、Bot 切换时的加载与已有内容、刷新失败保留内容、消息入场动画、设置分类草稿与凭据清理、能力选择一致性、归档版本、配置冲突草稿，以及跨 Bot 提交、稳定 requestId 重试、快照缓存复用、Runner 迟到响应隔离、跨设置分类的操作锁和 selector 订阅隔离。macOS 桌面历史冒烟覆盖三栏/两栏切换、新建 Bot 到聊天、详情导航、设置页返回与 UI 退出后 Runner 存活；本次 Bot 切换稳定化使用本地自动化测试与桌面目视验证，不将历史冒烟作为本次结果。

已知缺口：

- 已有库 Conversation 的 Bot 缺少「新建对话」入口，多会话能力目前只在 Bot 尚无 Conversation 时可达。
- `< 768px` 单栏布局未在真实窗口验证（桌面窗口 `minWidth` 为 960）。
- 主题与字号偏好尚未开放，通用设置页只有说明。
- [design.pen](../design.pen) 记录的是设计系统的历史来源，当前界面结构以本文件与源码为准。
