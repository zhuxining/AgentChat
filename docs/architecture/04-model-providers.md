# 模型供应商与凭据配置

本文描述供应商配置的应用边界和操作方式；产品决策来源见[配置规划](../research/llm-provider-configuration-plan.md)，上游 API 与版本依据见[调研](../research/pi-ai-providers.md)。最终字段以 `contracts/providers.ts` 与 Runner 运行时校验为准。

## 接入实例

供应商类型决定使用哪个 pi 内置 Provider，例如 `openai`、`deepseek`。接入实例是用户建立的一套独立配置，具有稳定 ID、展示名称、认证来源、连接参数和模型配置。同一供应商可以建立多个实例，Bot 和会话通过实例 ID 与模型 ID 引用模型；修改名称不改变身份。

设置中的“模型与 Provider”默认展示已连接供应商的单列列表，内置和自定义连接统一列出名称、状态与编辑入口，自定义连接额外提供删除入口；删除需要确认，并保留 Bot/会话引用保护。列表底部提供“添加模型提供商”。点击编辑或添加后进入配置表单，并可返回列表。表单顶部分为“第三方模型提供商”和“自定义模型 API”，选择提供商后直接填写认证凭证。API 地址和连接名称放在默认折叠的“自定义设置”，其他认证方式放在次级入口。同一供应商有多个连接时才显示连接选择器。新建的自定义 API 连接以 `custom: true` 标记，编辑时进入详细配置；列表统一展示所有连接。未带标记的旧配置仍使用内置表单，保留原始身份与引用。连接与模型定义保存后需要重新启动后台生效；页面显示待生效状态，保存本身不发起模型请求。

内置供应商的模型目录只提供选择、获取可用模型和添加自定义模型，不显示内置模型参数编辑。新连接首次保存时若尚未选择模型，默认选择目录中的第一个模型；用户之后可以调整。隐藏模型只影响后续选择，不使现有引用失效。自定义模型与自定义 API 提供详细配置；已有内置模型差异覆盖继续兼容，未覆盖字段随随包目录升级，自定义配置入口可恢复默认值。自定义模型需要符合对应 API 的完整定义。

常用字段通过表单编辑，复杂 `compat`、采样、价格等字段通过高级 JSON 编辑。两种方式操作同一份草稿。模型能力元数据与请求参数不同，字段存在不意味着每个适配器都消费它。请求级参数以当前 pi-durable 公开能力为边界，不通过类型断言或私有 API 扩展执行系统。

## 凭据来源

新建 API Key 连接默认使用系统凭据库，并显式保存 `auth.useEnvironment: true`：已保存密钥优先，未保存密钥时使用供应商公开解析器支持的环境认证。页面只显示环境变量名称与检测状态，不返回值；移除已保存密钥后可使用环境认证。留空输入框不会删除已保存密钥，替换或移除均由用户主动操作。已有连接保留原有认证规则，不自动启用环境回退；显式选择环境变量或凭据文件时不回退到其他来源。旧环境变量/文件连接也展示简单密钥表单：留空保留来源，填入新 Key 时改用本连接的系统凭据库；只有原来源为供应商标准环境变量时，替换后继续允许标准环境认证。

其他认证方式可以明确选择以下来源，读取失败不会自动切换账号或来源：

| 来源         | 配置与行为                                                                                      |
| ------------ | ----------------------------------------------------------------------------------------------- |
| 系统凭据库   | 使用应用服务命名空间内的条目；专门入口写入、替换和移除，不回显已存密钥                          |
| 环境变量     | 填写后台宿主环境中的变量名；只读，不修改 shell 或系统环境                                       |
| 独立凭据文件 | 使用数据目录 `credentials/` 下的相对 JSON 路径和条目名；通过专门入口写入明文 key 或整个环境引用 |

凭据文件格式为：

```json
{
  "entries": {
    "work-key": {
      "type": "api_key",
      "key": "${WORK_LLM_API_KEY}"
    }
  }
}
```

`key` 可以是密钥字面值，也可以是整个 `$VARIABLE` 或 `${VARIABLE}` 引用。不是任意 shell 模板，不执行 `!command`。普通配置、导出、模型定义和状态响应不包含解析后的 key。认证 Header 使用绑定本实例来源的 `${credential:entry}` 引用，不能利用 Header 引用读取其他条目。

OAuth 是独立认证方式，Token 保存在系统凭据库，通过供应商公开登录、刷新和退出接口维护。页面处理授权链接、设备码和文字、秘密、选择、手动代码提示；取消或离开进行中的登录流程会请求取消。

云环境认证按供应商公开规则处理 AWS 凭据链、Google ADC 等；project、location、region 等非秘密参数单独配置。不能把“没有 API Key”统一视为未配置。

环境变量由宿主读取。重启 Node 只能继承宿主已有环境；如果宿主本身仍是旧环境，需要从具有新环境的启动方式重启整个后台宿主。

## 保存、测试和生效

保存和测试是独立操作。测试使用已保存的实例及指定模型，包括尚未重启生效的配置，并返回配置版本、时间及结果。测试在隔离的模型集合内执行，不替换正在运行的 Harness 所用集合。测试可能产生供应商费用；成功仅证明该模型在该次请求成功，不证明整个目录都可调用。

配置修改后旧测试结果需要标明已过期。重启前的执行继续使用当前生效配置；页面明确显示待生效状态。重启会影响正在执行的任务，用户应在提示后选择时机；关闭/恢复仍交由 pi-durable 的公开接口负责。

被 Bot、默认配置或持久会话引用的实例、自定义模型不能直接删除。停用保留历史；停用配置在重启生效后，Provider 分派边界拒绝新的模型请求，也覆盖压缩与恢复路径，不只是禁用发送按钮。删除内置覆盖只恢复默认值。

## 安全与 IPC 边界

前端统一通过 `runnerClient.providerRequest` 调用 `runner_request`，共享 JSON 合同在 `contracts/providers.ts`。公开操作仅包含配置、状态、测试、凭据写入/删除及认证交互，不提供读取明文凭据的前端命令。

Node 到 Rust 使用同一私有 JSONL 的反向 `nativeId` 帧读取和写入凭据。该入口只由宿主持有的子进程触发，不开放给 WebView 或本机客户端。Rust 检查凭据格式和路径，文件限制在 `credentials/` 内，并处理权限、受限读取及原子替换。Node 通过 pi-ai `CredentialStore` 与 `AuthContext` 接入；OAuth 刷新读改写必须串行，多个模型集合共享同一来源的锁。

工具环境剔除认证变量。与应用同一系统用户运行的工具不构成完整 OS 隔离，不能把环境清理描述为密钥对同一用户完全不可访问。

OAuth 授权页在系统浏览器打开，不向远程页面授予本地 Capability。WebView 使用 CSP 限制脚本与连接来源，模型网络请求发生在 Runner。
