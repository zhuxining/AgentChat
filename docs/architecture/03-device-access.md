# Device Access

> **Status**: `active`（架构决策；Device Access 尚未落地）。

## 职责定位

Device Access 负责移动客户端访问 Host 的局域网协议、设备配对、Host 发现和凭据验证，不负责桌面 UI 的 Tauri Command、会话业务规则、Pi 运行或文件附件传输。

## 核心原则

- **仅已配对设备访问：** 局域网可达不等于已授权；Host 校验每台设备独立凭据。
- **证书信任随首次配对建立：** 移动端通过二维码取得 Host 证书指纹，后续使用 Rust 网络层验证 HTTPS。
- **Host 不可达时不伪造在线状态：** 手机只在已连接 Host 时发送消息；本地缓存只读展示已同步的近期会话。

## 边界与实体

### 输入

- **配对请求：** 移动端提交二维码中的一次性配对凭据与 Host 证书指纹。
- **已认证请求：** 移动客户端提交消息、读取会话、取消执行或对空闲聊天执行 `clear`。桌面 UI 通过 Tauri Command 直接调用同进程 Host，该调用不经过 Device Access。
- **Host 消息与 delta：** Host Runtime 返回持久化消息及在线 Run 的实时内容。

### 输出

- **设备登记结果：** 向 Host Runtime 提供新配对设备身份，或拒绝无效配对。
- **HTTP 响应：** 返回移动客户端请求的会话、消息和发送结果。
- **SSE 事件：** 将 Host 产生的在线 delta 与最终消息更新推送至已认证移动客户端。
- **移动端离线视图：** 展示客户端已缓存的近期消息，不接受离线写入。

### 核心实体

- **Device：** 已配对的移动客户端，拥有独立认证凭据并可被单独撤销。

Device Access 通过 Host Runtime 的设备登记接口保存设备身份、凭据校验值与撤销状态；它不直接访问 Host 的 SQLite 文件，也不保存原始设备凭据。一次性配对凭据是配对流程中的内存临时授权，不构成独立业务实体。存储归属见[数据存储](04-data-storage.md)。

### 错误边界

Device Access 负责拒绝无效凭据、错误证书和非授权设备；Host Runtime 错误映射为客户端可理解的响应，底层 TLS 与系统网络错误不会伪装为业务成功。

## 关键流程

### 设备连接与消息同步

1. 移动客户端首次扫描桌面端展示的一次性二维码，获得 Host 地址、证书指纹与配对凭据。
2. Tauri Rust 网络层校验 HTTPS 证书并完成设备配对；客户端把独立设备凭据写入系统安全存储。
3. 后续连接通过 mDNS 重新发现 Host，并以设备凭据建立 HTTPS 请求与 SSE 订阅；发现失败时，客户端提示用户重新扫描桌面二维码。
4. 客户端读取 Host 保存的消息；在线生成 delta 实时展示，最终响应由 Host 持久化。

移动端 Rust 在本机 SQLite 中只读缓存最近 20 个 Conversation、每个最多 100 条 Message、相关 Context Segment 摘要及所需的 Agent 摘要，不缓存 Pi Session 路径、Agent 记忆或设备凭据。重连后以 Host 数据更新并清除已从列表移除的记录；离线时展示最后同步时间和已同步的 `clear` 分隔。设备凭据和 Host 证书指纹由手机系统安全存储保管。

Pi stdout 读取不能等待 SSE 客户端发送。Host 为每个在线连接设置有界事件缓冲；连接持续落后时断开它，最终结果先写入 Host SQLite，再由客户端重连读取快照。流式 delta 不补放，也不在手机缓存中保留。网络层只能转发 Host 已转换的产品事件，不转发原始 Pi JSON、stderr 或工具调用内容。

群聊上线时，同一同步投影需加入群标题、成员摘要、消息发送者和群级 `clear` 边界；移动端提交 `@Agent` 或 `@all` 的目标标识，Host 统一校验和展开。手机仍不决定 Pi 路由或补读范围，目标缓存迁移见[数据存储](04-data-storage.md#群聊扩展v2-目标设计)。

## 设计决策与权衡

| 决策问题                       | 选择                                                                                 | 放弃的替代方案                                                | 理由                                                                            | 变更条件                                          |
| ------------------------------ | ------------------------------------------------------------------------------------ | ------------------------------------------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------- |
| 桌面和手机客户端采用什么宿主？ | 桌面、iOS 与 Android 客户端采用 Tauri，React 负责界面。                              | Electron、React Native、分别开发 Swift 与 Kotlin 客户端。     | 复用前端界面与 Tauri 宿主边界，并满足首发原生安装 App 的要求。                  | 目标平台验证发现 Tauri 移动端无法提供必要能力时。 |
| 首发如何连接 Host？            | 仅局域网连接；首次二维码配对，之后使用 mDNS 发现 Host。                              | 公网中继、VPN、远程隧道、每次手工输入 IP。                    | 保持 Host 本地优先，同时避免 DHCP 地址变化要求用户重复配置。                    | 外网访问成为首发必要体验时。                      |
| 客户端如何请求与接收事件？     | HTTPS 请求/响应处理客户端操作，SSE 推送 Host 到客户端的单向实时事件。                | 所有通信统一用 WebSocket。                                    | 当前客户端操作是请求/响应，实时消息方向主要从 Host 到客户端。                   | 产品需要持续双向高频消息时。                      |
| 移动端如何信任本地 Host？      | 一次性二维码交换 Host 证书指纹；Tauri Rust 网络层负责 TLS 校验并将 SSE 内容转交 UI。 | 要求用户安装系统 CA、依赖公开域名与局域网 DNS、忽略证书错误。 | 不依赖云中继或用户安装根证书，并保持 HTTPS 校验；需在 iOS 与 Android 真机验证。 | 平台测试无法可靠实现证书校验或 SSE 转发时。       |
| 配对后如何保存客户端身份？     | 每台设备使用独立凭据，移动端凭据存于系统安全存储，Host 支持单设备撤销。              | 所有设备共用长期密码、每次连接重新扫描二维码。                | 设备丢失时可单独撤销授权，避免重置其他客户端。                                  | 设备身份模型升级或增加多用户工作区时。            |
| Host 不在线时移动端提供什么？  | 缓存近期会话供离线只读；发送消息需要 Host 在线。                                     | 手机独立维护可写消息副本、离线队列和冲突合并。                | Host 是唯一消息事实来源；首发不引入多端离线写入与冲突解决。                     | 用户研究确认离线写入是必要能力时。                |
| 首发提供哪些客户端与内容能力？ | 首发提供 iOS/Android Tauri App；PWA、附件上传和后台推送不纳入首发。                  | 首发同时提供 PWA、文件/图片附件和推送服务。                   | 先验证原生多端对话与局域网 Host，不增加浏览器 TLS、文件同步和云通知边界。       | 移动 App 闭环成立且需求验证通过时。               |
